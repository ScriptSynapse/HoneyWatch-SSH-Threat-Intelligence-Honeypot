How it works

Three moving parts, one always-on server.

01 / DEPLOY

Put it where attackers already look

Run the honeypot on a small VPS, listening on port 22 (or 2222 while you test). It advertises a normal-looking SSH banner — nothing tips it off as fake.

02 / CAPTURE

Let the fake shell do the work

Once "in," attackers get a convincing filesystem and shell. Every login, command, and download attempt is logged with a tarpit delay to slow automated tools down.

03 / ANALYZE

Watch the picture form

The dashboard classifies attack patterns, enriches every IP with geolocation and abuse data, and alerts you the moment something looks critical.

🧩

Two parts, deployed separately — on purpose

The dashboard runs anywhere static sites do. The honeypot itself needs a real, always-on server, since something has to keep port 22 open around the clock. Browse this demo with zero setup, then point it at your own ws_server.py once you're running the real thing — see the README for a five-minute VPS setup.
